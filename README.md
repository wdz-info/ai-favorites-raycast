# AI 收藏夹 · AI Favorites for Raycast

独立的 Raycast Extension，用来收藏、检索和复用 Codex、Kiro、Grok 编程会话中的内容。会话、回复和文件均保存独立快照；原始记录删除后仍可阅读。当前本地版本为 0.5.2：Raycast 负责快捷操作，本地网页负责完整管理和阅读，双方共用同一份资料库。历史正文检索、上下文包、备份恢复及只读 CLI / MCP 均保留。

## 本地安装

需要 macOS、Raycast 和 Node.js 22.22.2 或更高版本。无需 AI 订阅、API Key 或云服务。

```bash
git clone https://github.com/wdz-info/ai-favorites-raycast.git
cd ai-favorites-raycast
npm ci
npm run dev
```

在下载的扩展目录运行。开发命令将扩展导入本机 Raycast 并监听改动，可在导入后停止监听。构建产物位于 `dist/`。当前通过源码安装，尚未发布到 Raycast Store。

| Raycast 命令       | 用途                                                |
| ------------------ | --------------------------------------------------- |
| 打开网页收藏夹     | 自动启动 / 复用本地服务，打开完整管理和阅读页面     |

| 浏览 AI 会话       | 浏览 Codex、Kiro、Grok 的历史，收藏会话、回复和文件 |
| 添加 AI 收藏       | 添加三类收藏，补充标签、备注、适用条件              |
| 搜索收藏           | 分区搜索收藏与历史正文，直接定位消息                |
| 收藏剪贴板         | 无需表单，直接保存文本并自动生成标题                |
| 同步 AI 历史       | 立即同步；后台按一分钟间隔扫描                      |

## 网页版与快捷打开

1. 重新加载扩展后，在 Raycast 搜索 **打开网页收藏夹**。命令自动启动本地服务并打开默认浏览器，再次运行会复用服务，无需手动启动终端。可在 Raycast 设置中为该命令分配全局 Hotkey。
2. Raycast 收藏夹操作菜单中按 **⌘⇧O** 打开网页；单条收藏的“在网页中阅读这条收藏”直接定位对应条目。网页沿用 Raycast 中配置的收藏目录和三个 Agent 历史目录。
3. 网页提供按来源、类型、项目、标签、验证状态筛选、全文检索及排序，支持 Markdown / 表格 / 代码阅读和复制；可编辑标题、标签、备注、适用条件，记录验证及使用反馈，删除收藏、比较版本及推荐版本。删除与编辑沿用原有快照规则。
4. 添加入口支持文字 / AI 回复、文件 / 目录绝对路径及 `file://` 链接。“从历史会话添加”会在弹窗内显示可搜索的会话列表；加载或失败时保留弹窗及提示，选中并成功打开会话后才关闭。之后可收藏整个会话或单条回复。回复保留对应问题，目录包含完整资源并可打开快照。网页历史按标题、项目和 ID 查找；历史正文检索继续使用 Raycast 的统一搜索。连续操作会复用 15 秒内的历史目录扫描；“刷新历史”可立即重新扫描。
5. 多选条目可生成带长度预算的上下文包。网页可下载包含目录资源的完整 JSON 备份，上传备份后先检查预览，再确认合并恢复。

网页直接读写原有 `favorites.json`。网页在重新获得焦点和每 15 秒刷新列表；Raycast 保留原有刷新逻辑，也可手动刷新。两端写入复用同一套加锁存储。

历史会话页面及添加弹窗使用两级分类：第一级为 Codex、Grok、Kiro 等程序，第二级为“今天 / 昨天 / 历史”。按会话最近更新时间及北京时间自然日判断；点击分类后在该分类内搜索和分页，分类数量统计完整搜索结果，避免只统计当前页。

服务仅监听随机端口的 `127.0.0.1`。Raycast 将启动凭证传给网页并保存在该网页会话中，无需账号和云服务。目录网页保留自己的脚本及相对资源，但使用独立沙箱身份，不能读取管理凭证。关闭浏览器后服务继续运行；网页侧栏“停止网页服务”可将其关闭，下次快捷打开时会重启。构建或配置变化后会替换旧服务，旧页面需重新打开。

也可从终端启动，命令会输出本机访问地址：

```bash
npm run web
# 自定义收藏目录
npm run web -- --storage /绝对路径/收藏资料库
```

`npm run dev` 和 `npm run build` 会先构建网页及独立服务。单独更新网页源文件后，运行 `npm run build:web`，再从 Raycast 重新打开。网页与服务资源位于 `assets/web/`；运行状态及启动日志位于资料库的 `web-service.json` / `web-service.log`，日志不记录请求或收藏正文。停止后的状态文件由下一次启动检查并更新，不以文件存在判断服务存活。

网页上传恢复上限为 128 MiB，更大的备份可使用 Raycast 的本地恢复入口。外部在线资源仍依赖网络，目录快照不会下载目录外的内容。

## 0.4 日常使用

- **找内容**：打开“AI 收藏夹”或“搜索收藏”，输入至少两个字符，结果分为“我的收藏”和“历史会话”。历史每个会话显示最相关的消息，Enter 阅读命中原文及相邻上下文，可继续浏览完整会话。消息的 ID、记录位置与来源保留。
- **快速保存**：给“收藏剪贴板”设置 Hotkey，运行即保存文本，默认标题来自首个非空行，来源诚实标记为“剪贴板（未关联会话）”。之后再编辑标签和备注。历史中的会话、回复、文件预览也提供“一键收藏”（⌘⇧S）。原有编辑后保存方式继续可用。
- **换个说法找**：操作菜单可切换“自然语言与模糊搜索”，使用中文分词、有限的中英术语扩展和单个拼写错误容忍，例如“死锁”可匹配 `deadlock`。这是词项检索，不是任意自然语言理解；精确关键词模式仍保留。
- **选对方案**：筛选表单支持验证状态和当前任务版本；失效收藏默认隐藏，可显式查看。匹配标题、正文和元数据后先按相关性排序，同等相关且项目与验证范围明确吻合时参考推荐和验证状态。其他环境验证过的方案会展示范围，不推断为当前任务已验证。Agent / 项目筛选同时作用于历史，类型 / 标签 / 验证筛选仅作用于收藏。
- **复用**：收藏操作菜单可复制原文或代码，生成上下文包，再记录“这次复用有用 / 这次未解决问题”。反馈独立保存，不改变原验证状态。

历史正文索引是独立、可重建的 `history-search.sqlite3`，不迁移或替换 `favorites.json`。首次搜索按需建立索引，界面显示进度和部分命中；已收藏内容可以立即搜索。“同步 AI 历史”每次用约四秒的索引处理预算分批补齐（单个会话的读取 / 事务可能超过该预算），前台搜索可继续完成。确认来源变化才更新对应会话，解析失败时保留已存在的索引版本并提示，较早的扫描不覆盖较新结果。退出后下次可继续已完成的部分。

索引包含本地会话文本，仅用户和 AI 可见消息，不采集推理或工具输出。首次建库耗时及占用取决于历史量；不保证瞬时完成。操作菜单可以重建索引，永久收藏不受影响。非常大的查询结果会提示缩小范围。

## 收藏与阅读

运行“浏览 AI 会话”，通过来源筛选选择 Codex、Kiro 或 Grok。选中会话按 `⌘ + Enter` 收藏整个会话；Enter 浏览消息和文件。选中 AI 回复按 `⌘ + Enter` 收藏回复，其快照包含此前用户问题及同一问题下的前一条回复。保存表单可以预览快照、设置标题、标签、备注和适用条件。

“添加 AI 收藏”→“文件或目录”支持选择文件、目录，或粘贴本地 `file://` 链接（含中文转义路径）。未关联会话时默认“手动来源”，也可指定来源 Agent 与项目目录。文件收藏保存打开表单时磁盘上的 UTF-8 内容，最大 8 MiB；带 SHA-256、保存时间和文件修改时间。同一路径内容变化后再次收藏，会保留两个独立版本。相同来源及内容重复收藏会保留原有元数据。不会从历史 patch 重建某次工具执行时的文件版本。

目录收藏会递归保存全部文件，包括二进制图片、CSS、JavaScript 和数据。选择 `index.html` / `index.htm` 会自动收藏其所在目录；选择目录时自动查找该入口。每个目录最多 2000 个文件、总计 64 MiB，不跟随符号链接；超限或读取时发生变化会报错，不会悄悄遗漏资源。没有入口页的目录也可以收藏并打开快照目录。

收藏后的“打开已收藏的网页快照”从资料库中的资源还原入口与相对目录结构，用默认浏览器打开；原目录被修改或删除仍能阅读旧版本。Raycast 内预览和检索使用入口 HTML 的静态可见文字（最多 15 万字符）及文件清单，不执行脚本；完整交互页面通过打开快照阅读。外部网址、目录外绝对路径和服务端能力不在快照内，页面原本依赖的在线服务仍需可用。

目录资源内嵌在资料库和 JSON 备份中，不依赖原文件；资源变化会保存独立版本。Obsidian 导出同时写出配套资源并在笔记中提供相对入口链接。打开时生成的 `directory-previews/` 只是可重建副本，可在关闭页面后清理，不影响已保存的版本。

收藏列表右侧直接显示 Markdown，Enter 打开阅读页。`⌘ + E` 编辑标题、标签、备注与适用条件，保留已保存内容。标签用英文逗号、中文逗号或换行分隔。精确搜索使用不区分大小写的 Unicode 规范化匹配，多个空格分隔词按 AND 匹配；可同时按类型、Agent、完整项目目录、标签和验证状态筛选。

操作菜单提供内容、代码、上下文、文件路径、来源位置的复制，以及原始记录定位。移除收藏会先确认；只移除收藏，不修改原始历史或文件。

## 自动同步与 Agent 格式

扩展的自动同步设置默认开启。首次安装后，在 Raycast 搜索“同步 AI 历史”，打开 Actions 并选择 **Activate Background Refresh**，启用每分钟后台扫描（调度受 Raycast 安装模式和生命周期限制；开发导入时若不调度，可手动运行同步或在前台搜索时补齐）。浏览及收藏界面打开时每 15 秒刷新。实际调度由 Raycast 管理，退出 Raycast、休眠或系统调度延迟期间不会保证准点执行；下次运行重新扫描。“同步状态”显示最近扫描、各来源最近完整同步、新增、变化、移除和读取提示。

同步保存独立的 `history-catalog.json`，通过文件状态与元数据识别来源变化。不会覆盖、升级或删除已收藏快照。来源变化时列表提示“来源已更新”；已确认移除时提示“来源已移除”。如果来源扫描失败或不完整，保留旧索引，避免把暂时不可读的历史当作已删除。首次扫描的缺失或损坏记录会显示提示。

| Agent | 当前支持的本地记录                                                                                                                                                          |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex | `sessions/`、`archived_sessions/` JSONL 与 `session_index.jsonl` 标题索引                                                                                                   |
| Kiro  | `~/.kiro/sessions/cli/` 的 CLI 元数据和 JSONL；新版 IDE 的 `session.json` / `messages.jsonl`；旧版 IDE workspace-sessions JSON；CLI SQLite conversations / conversations_v2 |
| Grok  | 官方 Grok CLI 的 `~/.grok/sessions/.../summary.json` 与 `updates.jsonl` 消息流                                                                                              |

仅预览用户消息与可见 AI 回复，排除推理、系统消息及工具输出。Grok 流式文本分片会合并；Kiro 同一消息 ID 的更新会替换未完成的显示版本。SQLite 使用 macOS 自带程序以只读模式读取指定会话表，不访问认证表。ProviderAdapter 保留后续 Agent 接入接口。Grok 网页聊天不是此适配器的数据来源。

## 上下文打包

打开“上下文打包”，按 Enter 选择或取消收藏，也可选择当前搜索结果。`⌘ + Enter` 进入打包，补充当前任务后选择“预览上下文包”，确认内容再复制。

可选择完整原文、精简片段或仅代码，默认最多 20000 字符，可设置 1000–200000。代码保留原位置，避免在方案和代码节重复输出；相同收藏 ID 去重。精简模式围绕当前任务词项截取原文，明确标注片段，不生成 AI 摘要。可排除条目和省略来源字段中的本机路径；这不会自动脱敏正文里的路径或内容。

问题、适用条件、标签、备注、验证状态、来源、收藏 ID 和快照用于追溯。超预算明确标记截取，原快照不变；未放入的条目会提示。缺失问题和适用条件不会由 AI 补写。复制前可阅读最终输出。单条收藏操作菜单也提供“生成上下文包”。

## 选中文字快捷收藏

建议在 Raycast 设置中给“选中文字快捷收藏”配置一个空闲 Hotkey。在来源应用中选中文字后直接运行命令，扩展先调用 Raycast 的选中文字 API；无结果或失败时读取剪贴板。两者都不可用时表单允许手动粘贴。

确认内容、标题、来源说明和来源 Agent，可选填写原始链接。剪贴板可能来自别的应用，因此不把当前应用自动当作剪贴板的来源。未确认来源时标记“手动来源”，不编造会话 ID。收藏保存读取方式与选中文字时取得的应用信息。

通过收藏夹内的操作菜单启动时，选区可能已不在来源应用，适合确认剪贴板后收藏。不同 AI 客户端的原生选区读取仍需逐个实测；当前验证记录明确区分 API 边界测试与真实桌面交互。

## Obsidian 导出

单条收藏操作菜单选择“导出到 Obsidian”；批量导出从独立命令或收藏夹操作菜单进入。多选后选择仓库目录及相对导出子目录。可在扩展设置中保存默认仓库，未设置时在表单选择。

每条收藏生成独立 Markdown 文件，YAML 属性保留标签、类型、Agent、ID、来源、快照、验证项目/版本/日期及推荐标记；正文保留备注、适用条件、用户问题、相邻回复、原始内容和来源。遇到同名文件会生成新文件，避免覆盖已在 Obsidian 编辑的笔记。导出结果逐条显示成功或失败，成功项可通过 Obsidian URI 打开，也可在访达定位。子目录不得跳出所选仓库。

## 版本与验证

收藏操作菜单选择“对比收藏版本”，优先列出同一来源的其他快照，也允许选择修正后的另一条回复。差异显示旧/新正文及上下文，支持阅读双方完整快照和复制差异。手动选择“推荐新版”或“推荐旧版”后，两个方案及既有版本归入同一版本组，组内只保留一个推荐标记，旧内容继续保存。推荐标记与验证状态分别管理；推荐不会自动变成已验证。

“记录验证状态”提供“未验证 / 已验证 / 已失效”。标记已验证时需要填写验证项目、版本和日期，可记录测试结果；失效时可记录原因。旧收藏默认未验证。状态在收藏列表、阅读页、上下文包和 Obsidian 笔记中显示。

## 用报错或代码找收藏

粘贴异常堆栈、代码片段或业务关键词。检索先提取异常名、类名和关键词，排除常见语言关键字；英文标识符按完整词项匹配，中文按关键词匹配。结果按权重和更新时间排序，展示命中词项及匹配分，可直接阅读、复制、打包或导出。

报错命令保留可解释的异常、类名和关键词检索。统一搜索另提供词项扩展和可选本地语义补充，见下文。检索限制与对照结果见 [检索评估](SEARCH-EVALUATION.md)。

## 来源定位、设置与数据

- Codex 会话使用 `codex://threads/<sessionId>`。本机应用代码已核对这个格式，实际桌面跳转尚未验收；可关闭链接。指定消息通过 JSONL 行定位，不生成未经验证的消息深链接。
- Kiro 提供会话 ID 复制；Grok 提供恢复命令复制，用户手动运行。原始消息可通过 JSONL 行、JSON 路径或 SQLite 记录定位。
- 文件打开操作指向磁盘当前版本；收藏预览显示保存版本。记录不可用时提示错误，快照继续可读。

| 设置                  | 默认                                                                   |
| --------------------- | ---------------------------------------------------------------------- |
| Codex 历史目录        | `CODEX_HOME` 或 `~/.codex`                                             |
| Kiro 历史目录         | `KIRO_HOME` 或 `~/.kiro`                                               |
| Kiro CLI 旧版数据库   | `~/Library/Application Support/kiro-cli/data.sqlite3`                  |
| Kiro IDE 旧版历史目录 | `~/Library/Application Support/Kiro/User/globalStorage/kiro.kiroagent` |
| Grok 历史目录         | `GROK_HOME` 或 `~/.grok`                                               |
| 收藏资料库目录        | `~/Library/Application Support/AI Favorites`                           |
| 自动同步              | 开启                                                                   |
| Codex 会话跳转        | 开启                                                                   |
| Obsidian 仓库与子目录 | 仓库需选择，子目录默认 `AI收藏`                                        |

收藏写入 `favorites.json`，文件权限 `0600`，新建资料库目录 `0700`。备份整个资料库可保留快照、上下文和元数据。修改目录是切换资料库，不自动搬迁。旧版收藏可直接读取，新字段均为可选。

收藏和同步目录分别使用进程间锁、临时文件、文件同步及原子替换。损坏数据会报错并保留原文件。如果异常退出留下 `.write-lock` 或 `.sync-lock`，先关闭相关命令并确认没有操作，再移除对应空锁目录。不要在保存时移除锁。扫描阶段不持有同步锁，提交索引时加锁，并防止旧扫描覆盖更新的结果。

扩展不主动上传日志、收藏或剪贴板，不修改 Agent 历史。复制会进入系统剪贴板；导出会写入用户选定的仓库；原始定位会交给对应本地应用。全局快捷键由用户在 Raycast 设置中选择，扩展不覆盖现有按键。

## 备份与恢复

在收藏夹操作菜单打开“备份与恢复收藏”，选择备份目录，创建带时间戳的新 JSON 文件。文件含全部快照和元数据、格式版本与校验和，使用 `0600` 权限；不覆盖已有备份。恢复时先选文件、检查并预览，再执行合并。

重复快照保留当前备注；相同 ID 对应不同快照时生成新 ID，保留双方内容。导入的版本关系继续保留，已有手动推荐优先。校验失败或资料库损坏时不写入原资料库。索引可以重建，无需备份。备份文件本身包含收藏正文，应存放在自己的目录。

## CLI 与只读 MCP

在扩展目录完成 `npm ci` 后：

```bash
npm run build:cli
node build/ai-favorites.cjs search "RetryPolicy"
node build/ai-favorites.cjs search "死锁" --mode smart
node build/ai-favorites.cjs get FAVORITE_ID --offset 0 --max-chars 4000
node build/ai-favorites.cjs pack FAVORITE_ID --task "当前任务" --pack-mode compact --max-chars 12000
node build/ai-favorites.cjs history "timeout"
```

默认与 Raycast 使用同一资料库。若 Raycast 配置过自定义目录，添加 `--storage /绝对/资料库目录`，或设置 `AI_FAVORITES_STORAGE`。`history` 是显式读取并建立本地 Agent 历史索引的命令；其他读取命令只读收藏，不自动开放全部历史。输出为 JSON，错误写到 stderr。

MCP 使用官方 TypeScript SDK，通过 stdio 提供 `search_favorites`、`get_favorite`、`build_context_pack` 三个只读工具；搜索先给片段与 ID，原文按 ID 分页读取。以下是需要自行添加到所用客户端的配置示例，本项目不会修改 Agent 配置：

```json
{
  "mcpServers": {
    "ai-favorites": {
      "command": "/绝对路径/node",
      "args": ["/绝对路径/ai-favorites-raycast/build/ai-favorites.cjs", "mcp"]
    }
  }
}
```

`node` 路径可通过 `command -v node` 获得。先构建 CLI，再配置其绝对路径；更新源码后重新构建。客户端配置格式可能不同，上述示例使用 `mcpServers` 形式。MCP 不执行历史内容中的命令，也不提供删除、修改收藏或任意路径读取。历史文本由客户端作为资料判断；若调用 Agent 使用云模型，取出的内容会进入该 Agent 的模型上下文。

## 可选的本地模型语义检索

默认不包含、下载或运行模型。已有 Ollama 服务与嵌入模型时，在 Raycast 设置填写“本地嵌入模型”，按需填写服务地址，然后在操作菜单选择“本地语义混合搜索（实验）”。地址仅支持 loopback，默认 `http://127.0.0.1:11434`，不会转发重定向。

CLI 可使用 `--embedding-model <已安装模型名称>` 与 `--embedding-endpoint <本机地址>`，或环境变量 `AI_FAVORITES_EMBEDDING_MODEL`、`AI_FAVORITES_EMBEDDING_ENDPOINT`。输入是收藏检索文本的前 12000 字符，查询最多 2000 字符；向量缓存 `favorite-vectors.json` 按内容哈希、模型和地址区分。精确命中保持在前，语义只补充缺失结果。未配置模型、服务失败、超时或维度不一致时显示提示并回退词项检索，原收藏保持不变。

模型质量取决于所选模型，特别是中文和跨语言能力。当前只验证了服务接口、缓存及回退，没有在本机真实嵌入模型上验证召回质量，因此保留为手动选择的实验能力。[官方 Ollama 嵌入接口](https://docs.ollama.com/api/embed)、[官方 MCP 开发文档](https://modelcontextprotocol.io/docs/develop/build-server)。
